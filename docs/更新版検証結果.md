## Docker で残っている確認

この開発 PC の Docker Desktop は、`desktop-linux` の接続先 `dockerDesktopLinuxEngine` パイプに接続できませんでした。原因は特定できておらず、Docker データの削除、初期化、WSL のリセットはしていません。

Docker が正常に起動した開発環境で、次を実行します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-security-update.ps1
```

このコマンドは本番の Compose とは別のファイル・プロジェクト・一時 DB を使い、Docker イメージのビルドから業務操作まで確認します。本番の保存ボリュームを参照しません。成功後にこの文書の Docker 検証の状態を更新してから、[職場 PC の更新手順](職場PC更新手順.md)へ進みます。

更新・復旧スクリプトは Windows PowerShell 5.1 互換の構文と UTF-8 BOM で保存しています。初版は Windows PowerShell 5.1 の構文確認を行い、最終版の Docker コマンドを模擬したテストは PowerShell 7.6.5 で 23 件成功しました。正常な更新・復旧、通常イメージの参照の切り替え、ビルド失敗時にアプリを止めないこと、古いダンプ・不正形式・失敗ログで事前停止することを確認しています。復旧の1行コマンドは最新の保存状態を対象にし、ビルドだけで失敗した場合には元のアプリを確認して保持します。最終版の Windows PowerShell 5.1 と実 Docker を組み合わせた実行、および職場 PC での更新・復旧は未検証です。

模擬テストは `scripts/test-production-helpers.ps1` に保存しています。Node.js / PostgreSQL のテストは終了し、この作業で起動した検証用アプリと PostgreSQL は停止済みです。ソースの変更はローカルにあり、GitHub への反映と職場 PC の更新は行っていません。

## 依存関係の監査と残る課題

`npm audit --omit=dev` の結果は、Critical 0、High 0、Moderate 2（ExcelJS とその依存 uuid。元の指摘は同じ 1 件）です。uuid の指摘は `v3()` / `v5()` / `v6()` の出力バッファー境界チェックに関するもので、今回確認した ExcelJS 内の呼び出しは `v4()` でした。これは利用箇所からの判断であり、依存関係の監査が完全にゼロになったという意味ではありません。[uuid 公式アドバイザリ](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq)

また、既存の `/api/register` や `/api/formalin` などには認証・権限チェックのないルートがあります。今回の更新は Node.js / Next.js と依存関係、更新・復旧手順が対象です。API の権限制御は別の修正課題として残っており、ネットワーク内の端末からの不正操作への対策も必要です。
